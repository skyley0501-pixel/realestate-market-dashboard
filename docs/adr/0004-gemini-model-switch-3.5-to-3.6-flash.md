# 0004: デフォルトGeminiモデルを`gemini-3.5-flash`から`gemini-3.6-flash`に変更した件

- ステータス: 決定済み
- 日付: 2026-08-15（Phase3 Day37）

## コンテキスト

Day37で`NaturalLanguageQueryParser`（自然文→検索条件JSON変換）を実装し、結合テストで「渋谷区で築10年以内5000万円台」を実際にGemini APIへ投げたところ、`municipalityName`が期待した「渋谷区」ではなく文字化けした文字列（例:「戀茷匸」）で返ってくる現象を確認した。

同じプロンプトを5回実行して原因を切り分けた結果は以下の通り。

| モデル | 結果 |
|---|---|
| `gemini-3.5-flash`（Day33〜36で使用していたデフォルト） | 5回中4回、日本語固有名詞が文字化け |
| `gemini-2.5-flash` | 新規ユーザーには提供終了（404エラー、`models/gemini-2.5-flash is no longer available to new users`） |
| `gemini-3.6-flash` | 5回中5回、正常な出力 |

短い単純なプロンプト（「〜からJSONで抽出して」の1行）では`gemini-3.5-flash`でも文字化けしなかったため、フィールド説明や選択肢列挙を含む複雑な指示文で発生しやすい傾向がある。原因はモデル側のトークナイゼーション・日本語処理の不安定さと考えられ、アプリケーション側のコード（`z.toJSONSchema()`が生成するスキーマ含む）に問題は無いことをデバッグスクリプトで確認済み。

また同時に、`gemini-3.5-flash`の無料枠が**1日20リクエスト**という想定より厳しい制限（ADR 0003作成時点の一般的な調査結果「250回/日」とは異なる、モデル固有のクォータ）であることも判明した。

## 決定

- `GeminiLlmClient`のデフォルトモデルを`gemini-3.6-flash`に変更する（[llm-client.ts](../src/features/conversation/infrastructure/llm-client.ts)）
- `gemini-2.5-flash`は新規ユーザー提供終了のため使用しない（10月の廃止を待たず、既に選択肢から外れている）
- 無料枠のクォータはモデルごとに個別に管理されている可能性が高く、新しいモデルほど厳しい暫定クォータが設定されることがある、という前提で今後もモデル変更時は事前に結合テストで動作確認する

## 影響

- Day33〜36で作成済みのコード（`DEFAULT_GEMINI_MODEL`定数を参照するのみ）は変更不要。定数の値のみ更新
- 既存の結合テスト（`llm-client.integration.test.ts`）を新モデルで再実行し、正常動作を確認済み
- 今後、日本語の固有名詞を含む構造化出力を新規に実装する際は、単発の疎通確認だけでなく複数回実行して文字化けの再現性を確認する
