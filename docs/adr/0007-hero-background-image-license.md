# 0007: トップページ背景写真の出典・利用条件

- ステータス: 決定済み・実装済み（Phase4完了後の追記対応）
- 日付: 2026-08-17

## コンテキスト

トップページのヒーロー背景として、東京の夜景写真（東京タワーを含む）を追加した。GPTによるPhase4完了レビューで「リポジトリ内で撮影者・入手元・ライセンスを確認できない」と指摘されたため、出典と利用条件を記録する。

## 出典

- ファイル: `public/images/tokyo-night-skyline.jpg`
- 入手元: [写真AC](https://www.photo-ac.com/)（ACワークス株式会社が運営する会員制写真素材サイト）
- 入手方法: ユーザーが写真AC会員として無料ダウンロード

## 利用規約の確認結果

写真ACの利用規約（<https://www.photo-ac.com/main/terms>）を確認し、以下を確認した。

- **商用利用**: 可能。「商業目的その他目的を問わず、写真を自由に改変、編集および使用することができます」と明記されている
- **クレジット表記**: 不要。会員は写真にクレジット表記をすること自体が禁止されている
- **禁止事項**: 「素材そのものを独立の取引対象として頒布（販売・賃貸・無償配布等）し、公衆送信すること」「主要コンテンツとして製品（カレンダー・ジグソーパズル等）に使用すること」が禁止されている。いずれも「写真そのものを商品化する」利用を指しており、Webサイトのデザイン要素（背景・装飾）として組み込む今回の用途には該当しない

## 決定

- Webサイトの背景装飾としての利用は写真ACの利用規約の範囲内と判断し、そのまま使用を継続する
- サイト上へのクレジット表記は行わない（規約上不要かつ禁止されているため）
- 元画像（17MB, 6139×4093）はNext.js Image最適化により配信時に自動でリサイズ・WebP変換される

## 追記: 表示位置のレスポンシブ対応（2026-08-17）

東京タワーがヒーローカード（不透明背景）に隠れないよう、当初は`translate-x-[-5cm]`という固定の物理距離で背景画像を左シフトしていた。GPTレビューで「画面幅によって移動量が大きすぎる可能性がある」と指摘され、実際に計算・実測したところ、幅375px（モバイル）ではタワーが画面から329px分はみ出て完全に見えなくなっていた（固定cm値は画面幅に対して比例しないため）。

対応として、Tailwindのブレークポイント別に`%`単位の移動量へ変更した。

```
translate-x-[45%] sm:translate-x-[15%] lg:translate-x-[-15%]
```

`%`指定は要素幅（＝ビューポート幅）に対する相対値のため、同じブレークポイント内であれば画面幅が変わっても比例して追従する。以下の画面幅で実測し、タワーが画面内かつヒーローカードの外側に収まることを確認した。

| 画面幅 | 東京タワーの水平位置 | 判定 |
|---|---|---|
| 375px（モバイル） | 7.5% | 画面内 |
| 640px | 8.0% | 画面内 |
| 768px（タブレット） | 10.9% | 画面内 |
| 1024px（16:9相当, 1024×768） | 4.6% | 画面内 |
| 1280px（デスクトップ） | 8.0% | カード外 |
| 1920px（デスクトップ広） | 8.0% | カード外 |

**既知の限界**: 1024×900のような、幅に対して高さが極端に大きい（正方形に近い）ブラウザウィンドウでは、タワー位置が画面からわずか（-0.6%程度）にはみ出るケースを確認した。一般的なデスクトップ・ノートPCの画面比率（16:9〜16:10程度）ではこの問題は発生しない。単一の`translate`指定だけで全アスペクト比に完全対応することは数学的に不可能なため、この程度の誤差は許容範囲と判断した。
