# 0003: AIプロバイダをGeminiに決定し、OpenAI/Claudeは差し替え候補のスタブに留めた件

- ステータス: 決定済み
- 日付: 2026-08-15（Phase3 Day33/34）

## コンテキスト

`docs/design.md`（初版）およびロードマップDay33/34は、AIプロバイダとして「OpenAI実装 → Claude実装」の順で作る想定だった。しかしDay33の実装着手前に無料枠の有無を調査したところ、以下が判明した（2026年8月時点）。

- **OpenAI API**: 恒久的な無料枠は無い。新規登録時の少額トライアルクレジット（$5程度）も2025年半ばに廃止され、現在は付与自体が不安定
- **Claude API**: 恒久的な無料枠は無い。新規登録時に$5程度のトライアルクレジットのみ（SMS認証必要）
- **Gemini API**: Google AI Studio経由で**クレジットカード登録不要の無料枠が現在も存在**。2026年4月以降Proモデルは有料専用になったが、**Flash/Flash-Liteモデルは引き続き無料**（Flash: 10RPM/250回/日、Flash-Lite: 15RPM/1000回/日）

個人開発のポートフォリオであり、応募直前に想定外の課金が発生する構成は避けたい。

## 決定

- デフォルトのAIプロバイダを**Gemini API**（`GeminiLlmClient`、モデルは`gemini-3.5-flash`固定）とする
- `LlmClient` interfaceによるプロバイダ非依存の抽象化設計（design.md 7.2節）は維持し、ポートフォリオとしての「差し替え可能な設計」というアピールポイントは残す
- `OpenAiLlmClient`/`ClaudeLlmClient`は`LlmClient`を実装するクラスとして用意するが、実際のAPI呼び出しは行わず、呼び出されると「無料枠が無いため未実装」という趣旨のエラーを明示的に投げるスタブとする
- `container.ts`の`AI_PROVIDER`環境変数は`gemini`（デフォルト）/`openai`/`claude`を受け付けるが、`openai`/`claude`を指定した場合はスタブが呼び出し時にエラーになる

## 有料化防止のガードレール

- `GeminiLlmClient`のコンストラクタで、モデル名に`pro`を含む場合は例外を投げて拒否する（Proモデルは有料のため）
- **このAPIキーのプロジェクトにGoogle Cloud ConsoleでBillingアカウントを紐付けない**ことを運用ルールとして厳守する（紐付けない限り、無料枠超過はレート制限エラーになるだけで自動課金されない）
- 詳細は`docs/design.md` 7.2節「無料枠を維持するための注意点」を参照

## 影響・今後

- Day41〜43（AIチャット機能）実装時は、Gemini無料枠のレート制限（Flash: 10RPM/250回/日）を踏まえたIPベースのレート制限を必ず設ける
- 将来的に有料プランへの移行や別プロバイダへの切り替えを検討する場合は、`OpenAiLlmClient`/`ClaudeLlmClient`の中身を実装するだけで済む設計になっている
