# 0005: 駅距離データの取り込み方法を調査、Phase3では見送り

- ステータス: 調査完了・実装は見送り
- 日付: 2026-08-15（Phase3 Day40完了後）

## コンテキスト

ADR 0001（Phase1では駅検索・駅情報を提供しない）にて「駅情報が必要になった場合は、将来的に国土数値情報（駅データ）等の別データソースと、住所・町名ベースの突合処理を追加する（Phase2以降で検討）」とされていた。

Day40で価格予測フォームに「駅からの徒歩分数」を入力欄として実装した際、この入力が実データの裏付けを持たない自己申告値であることが判明した（詳細はDay40のコミット・article-notes参照）。これを受けて、実際に代替データソースで駅距離を取り込めるか調査した。

## 調査結果

### 使えるデータソース

1. **国土数値情報「鉄道データ」（N02、国土交通省）**
   - 駅の緯度経度・駅名・路線名を含むGeoJSON/シェープファイル。2025年度版が最新
   - ダウンロード形式（API無し）: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02-v2_3.html
   - ライセンス: 政府標準利用規約（無償・商用利用・改変可）

2. **国土数値情報「位置参照情報」（同、国土交通省）**
   - 「大字・町丁目レベル位置参照情報」: 都道府県・市区町村・町丁目名 → 緯度経度の対応表
   - ダウンロード: https://nlftp.mlit.go.jp/cgi-bin/isj/dls/_choose_method.cgi

3. 不動産情報ライブラリ自体には「XKT015: 駅別乗降客数」APIがあるが、**位置情報（緯度経度）は含まれない**ため、現行の`REINFOLIB_API_KEY`だけでは完結しない

### 実装アプローチ（案）

既存の取引データ（`data/reinfolib/*.json`）を確認したところ、`DistrictName`（町丁目名、例:「平河町」）と`MunicipalityCode`のフィールドを既に保持していることを確認した。これを使えば以下の流れで概算が可能。

1. 「鉄道データ」を取り込み、駅マスタ（緯度経度付き）を構築
2. 「位置参照情報」を取り込み、`DistrictName`から町丁目の代表点（緯度経度）を求める
3. 町丁目の代表点と各駅の直線距離を計算し、最寄駅・概算距離を算出（分速80m等で徒歩分数に換算）

### 精度の限界

取引データには番地までの住所が無く町丁目名までしかないため、算出できるのは「その物件そのものの正確な駅距離」ではなく「町丁目の代表点からの概算距離」に留まる。同一町丁目内でも駅への近さは物件ごとに異なるため、この限界はデータ構造上解消できない。

## 決定

- Phase3（Day41〜44: AIチャット・レート制限）を優先し、駅距離の概算取り込みは今回実装しない
- 本ADRを調査記録として残し、将来のPhase（運用フェーズでの拡張検討、または個別のIssue化）で本格実装を検討する際の起点とする
- Day40のフォーム注記（「駅距離は実データに基づかない参考値」）は、本機能が実装されるまで維持する

## 影響

- `PredictionInput.timeToStationMinutes`は当面ユーザー自己申告値のまま
- 将来実装する場合は、新規マスタテーブル（駅・町丁目代表点）、データ取り込みバッチ、突合・距離計算ロジックの追加が必要（現在のロードマップには含まれていない追加スコープ）
